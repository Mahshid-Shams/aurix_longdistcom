# AURIX: Long-Distance Wireless Communication

A UART wireless link between two Infineon AURIX TC375 Lite Kit boards, using HC-12 433 MHz transceiver modules.

Group project for the course *ICT for Industrial Applications*, Department of Information Engineering, University of Padova (2024). The lab work was carried out together with engineers from Infineon.

## Overview

The HC-12 module replaces a wired UART connection with a half-duplex radio link. Each AURIX board sends and receives UART data through its own HC-12 module, so the two boards can exchange data without a cable.

The project starts from the Infineon example `ASCLIN_UART_1_KIT_TC375_LK`, which sends "Hello World!" in loopback on a single pin. We modified it to drive the HC-12 module on external pins.

## Hardware

- 2 × Infineon AURIX TC375 Lite Kit
- 2 × HC-12 wireless module (channel 1, 433.4 MHz)

| HC-12 pin | AURIX TC375 Lite Kit |
|-----------|----------------------|
| VCC       | +3V3                 |
| GND       | GND                  |
| RXD       | P33.12 (UART TX)     |
| TXD       | P33.13 (UART RX)     |
| SET       | GND for AT command mode; disconnected for data transmission |

## Code changes

| File | Change |
|------|--------|
| `Cpu0_Main.c` | Added a 500 ms wait before the UART module is initialised |
| `ASCLIN_UART.c` | Baud rate set to 9600 bps, RX/TX pins moved to P33.13/P33.12, receive buffer size set to 100, expected number of received bytes set in `g_rx` |
| `IfxAsclin_Asc.c` | Prescaler and oversampling factor set manually |
| `IfxAsclin.c` | Numerator and denominator of the fractional divider set manually |

## The baud-rate problem

The first test was to send `AT` to the module and wait for the reply `OK`. The board received a reply, but it was not `OK`.

A logic analyzer on P33.12 and P33.13 showed that the HC-12 was transmitting at 9600 bps, while the AURIX was transmitting at a different rate from the one defined in the code. The baud-rate setting in the example project was wrong for this board.

The AURIX baud rate is generated by a divider chain:

```
BAUDRATE = (f_A × NUMERATOR) / (PRESCALER × DENOMINATOR × OVERSAMPLING)
```

The user manual gives values for 9600 bps with a clock `f_A` of 100 MHz. On our board `f_A` is 200 MHz, so we halved the numerator from 48 to 24:

| Parameter    | Value |
|--------------|-------|
| f_A          | 200 MHz |
| Prescaler    | 10 |
| Numerator    | 24 |
| Denominator  | 3125 |
| Oversampling | 16 |

```
200 000 000 × 24 / (10 × 3125 × 16) = 9600 bps
```

With these values the module answered `OK`.

## Result

1. With SET connected to GND, each board received `OK` in reply to `AT`, which confirmed the wiring and the baud rate.
2. With SET disconnected, one board was set as transmitter (write only) and the other as receiver (read only). The message "Hello" sent by the first board was received correctly by the second.

## Limitations

The project shows that the link works with a short text message. We did not measure the range, the packet loss or the behaviour with sensor data, so these remain open for future work.
